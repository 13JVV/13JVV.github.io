113명은 생성형 AI 구독 선택 실험의 유효 응답자입니다

113 valid respondents in a generative AI subscription choice experiment

신기술 시장분석 · 4인 팀 · 2026년 1학기

New Technology Market Analysis · team of 4 · Spring 2026

가격, 정확도, 보안성, 개인화, 전문성 중 무엇이 구독 선택을 좌우하는지 이산선택실험으로 측정했습니다.

팀장으로 설문 설계를 맡아 제시 순서를 바꾼 두 버전으로 배포했습니다.초안에서 모든 속성이 앞서는 선택지를 발견해 일정을 늦추고 속성 수준을 다시 정했습니다.

예상과 달리 1순위는 정확도(16.4%)가 아니라 전문성(26.4%)이었습니다.

We measured which of price, accuracy, security, personalization and expertise drives a subscription choice, using a discrete choice experiment.

As team lead I designed the survey and shipped it in two question orders. When the draft had options that beat others on every attribute, I delayed the schedule and reset the attribute levels.

Against our hypothesis, the top attribute was expertise (26.4%), not accuracy (16.4%).

Team of 5 from four majors

  1. 공통 문제부터 정했습니다네 전공이 서로 다른 말로 안전을 볼 때, ‘한정된 순찰 인력과 정비 예산을 어디에 먼저 쓸까’라는 자원 배분 문제로 다시 정의했습니다.
  2. 산출물을 한 흐름으로 묶었습니다위험 정량화, 디지털 트윈, 정책, 물류, 엣지 인프라로 나누되 모두 상태, 행동, 결과의 흐름에 연결되게 조율했습니다.
  3. 제 안을 내려놓았습니다전공별 제안이 부딪히자 두 대시보드 안을 직접 만들어 비교했고, 팀원 전문성이 더 드러나는 안을 채택해 제 초기 안을 고쳤습니다.
  1. Set one shared problemI reframed campus safety as a resource allocation question: where to send limited patrol staff and repair budget first.
  2. Tied every output into one flowRoles were split by major, but every output had to connect to one state, action, result flow.
  3. Let go of my own draftWhen proposals clashed, I built two dashboard options, compared them, and adopted the one that showed my teammates' expertise better.

BigContest AI Data Capstone

4인, 산업경영공학과 · 사회적 고립 예방 AI 에이전트

Team of 4 · AI agent for preventing social isolation

  1. 일하는 규칙부터 세웠습니다main 직접 푸시를 막고, 기능별 브랜치와 팀원 확인 뒤 병합하는 규칙을 정했습니다.
  2. 데이터가 새지 않게 막았습니다공모전 원본 데이터와 API 키는 커밋 단계의 훅으로 저장소에 올라가지 않게 했습니다.
  3. 같은 근거로 판단하게 했습니다ERD, 회의 정리, 의사결정 로그를 문서로 남겨 팀원이 같은 자료를 보고 결정하게 했습니다.
  4. 가장 무거운 부분을 맡았습니다문제 정의와 분석 설계, 데이터 파이프라인, 위험도 모형, 에이전트, 정수계획 최적화를 구현했습니다.
  1. Set working rules firstNo direct pushes to main; feature branches merged after a teammate's review.
  2. Kept data from leakingCommit hooks blocked raw contest data and API keys from the repository.
  3. Made decisions on shared evidenceAn ERD, meeting notes and a decision log kept everyone on the same page.
  4. Took the heaviest partI built the problem framing, pipeline, risk model, agent and integer-programming allocation.

I ship an MVP that tests one core hypothesis, then add features after seeing real usage and store review notes.

02실험계획 · 선택모형Experiment design · choice model

사용자 선호는 숫자로 측정합니다

Measure preference in numbers

“다 중요하다”로 끝나는 평점 대신 사용자가 무엇을 포기하고 고르는지 선택 실험으로 재고 우선순위를 정합니다.

Instead of ratings where everything is "important", I measure trade-offs with choice experiments and set priorities from them.

03수리최적화 · 시뮬레이션Optimization · simulation

한정된 자원은 최적화로 나눕니다

Allocate scarce resources by optimization

인력과 예산이 모자랄 때 어디에 먼저 쓸지를 목적함수와 제약식으로 풀고, 바꾸기 전에 시뮬레이션으로 비교합니다.

When people and budget run short, I solve where to spend first with an objective and constraints, and compare options in simulation before changing anything.

04검증 설계Validation design

AI 결과에는 검증 기준을 붙입니다

Attach a test to every AI result

AI가 만든 결과는 정답을 아는 데이터로 시험하고, 틀릴 수 있는 지점에는 사람이 확인하는 단계를 넣습니다.

I test AI output against data with known answers, and put a human check where it can go wrong.
